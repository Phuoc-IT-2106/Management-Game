Director task and DEC-023. Prototype review by assigned UX/UI engineering role;
final recommendation is advisory, not an accepted project decision.

Question: does the map earn its space and interaction complexity against a
structured company tree? Exactly one refined variant of each, same snapshot,
IDs, inspector, Affairs, navigation and return contract. No live integration.

No new reusable component. Local header uses existing brand resolution and token
roles; it does not alter NavigationContext or other kit consumers. No graph,
recursive tree framework, command, Domain/Application, save or identity changes.

Verification: preserve pure/native Stage 2/3 checks; add semantic compression,
branch fallback, persistent header/path, compact Affairs, action visibility,
same snapshot/selection, 720p long-name + alternate branding, return, callback and
node retention checks. Capture five matched states × two views × two viewports.
Record geometry, retained nodes and action counts as ENGINEERING PROXIES, never
human comprehension, satisfaction or task-time proof. Evaluate all five task
scripts with an explicit starting state and counting convention.

Decision: prefer list-first if task access/context are equivalent at lower
structural cost and no measured human advantage warrants the map. Do not start
Stage 4. Preserve historical Stage 3 evidence and all governance decisions.
