# Refined structured company tree

One reading order: company → portfolio → compressed Esports/Discipline pair →
team, followed by a separately titled shared-function group. Indentation carries
ownership; matters align beside their owner. Parent navigation still follows all
five semantic scopes, even though two appear on the same row.

The company root and every intermediate scope remain clickable. Functions are
explicitly labelled shared support and never appear beneath the team. Selecting
the team exposes both support relationships and direct links in the common
inspector. The same sponsor/preparation ID selects the same evidence in either
view. Toggling mode does not create a second snapshot or selection.

Only rows with attached matters need a horizontal owner/matter composition;
ordinary scopes use a native margin and canonical EntityLabel. Two compact group
headings replace repeated explanatory subtitles. Scope buttons align to the top
of taller matter groups. No native recursive Tree adapter, new reusable control,
virtualization, business logic or menu framework.

Strength: one sequential hierarchy, fewer representation Controls and fewer
relationship/grouping decorations. Weakness: stacked groups consume more vertical
space; specific support relationships need the shared inspector. It can resemble
an administrative tree. Persistent company identity, owned scopes, consequences
and exact return are therefore part of this model, not optional decoration.
