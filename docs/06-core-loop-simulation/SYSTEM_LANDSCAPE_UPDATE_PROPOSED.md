# PROPOSED PHASE 2 UPDATES TO SYSTEM_LANDSCAPE.md

Status: PROPOSAL — clarification of simulation responsibilities, not software architecture

## 1. Add State Boundary Clarification

**PROPOSAL**

Add near the top:

> Phase 2 distinguishes `Company State` from `World State`. System names in this document describe simulation responsibilities and relationships, not software modules or implementation architecture.

## 2. Clarify Company Core for First Slice

**PROPOSAL**

For the first vertical slice, the active Company Core subset is:

- finance / liquidity;
- capital allocation;
- contracts;
- company reputation;
- audience linkage;
- organizational capacity;
- key staff / delegation;
- risk / recovery;
- executive strategy.

Brand, infrastructure, broad legal detail, deep relationships, and advanced analytics remain future/deferred unless a prototype need is demonstrated.

## 3. Clarify Market & World for First Slice

**PROPOSAL**

The active World subset is:

- rival organizations;
- competition calendar/results;
- limited talent market;
- limited sponsor market;
- audience/commercial environment;
- optional lightweight meta / market condition.

Do not add a global economy.

## 4. Clarify Esports Domain Responsibilities

**PROPOSAL**

The first-slice Esports domain owns gameplay concepts for:

- roster;
- coach / competitive staff;
- preparation;
- competition inputs and results;
- discipline-specific strategic choices at abstracted depth.

Full tactical match execution remains excluded.

## 5. Clarify People Layer

**PROPOSAL**

For Phase 2, only simulate person attributes that affect:

- competitive capability;
- contract/value decisions;
- recommendation/delegation quality;
- availability;
- development at abstract depth.

Do not activate all candidate personality/relationship attributes by default.

## 6. Clarify Decision & Event Layer

**PROPOSAL**

Decision triggers are generated by:

- deadlines;
- threshold crossings;
- scarce opportunities;
- objective conflicts;
- material new information;
- rival actions;
- staff escalations;
- failure/recovery transitions.

Routine non-decisions resolve automatically.

## 7. Add Cross-System Rule

**PROPOSAL**

> Material consequences should update authoritative state or scheduled commitments. Avoid mechanics that create isolated bonuses with no effect on future decisions.
