# RIVAL SIMULATION

Status: Phase 2 — Core Loop & Simulation specialist proposal

## 1. Goal

**DECISION — inherited**

Rivals must evolve and compete in the same ecosystem. They must not remain static background entities.

**PROPOSAL**

The first vertical slice needs rivals only at the fidelity required to create:

- competitive pressure;
- talent-market scarcity;
- sponsor-market scarcity;
- changing prices / availability;
- visible strategic adaptation.

It does not need full symmetric CEO simulation for every rival.

## 2. Minimum Rival Ecosystem

**PROPOSAL**

Use **five rival organizations** as the default minimum test ecosystem, creating six active organizations including the player.

Reasoning:

- enough opponents for standings and repeated rivalry;
- enough buyers to create talent competition;
- enough organizations to create sponsor scarcity;
- small enough for causal changes to remain readable.

**ASSUMPTION**

The exact competition format may later require a different count. The simulation requirement is therefore **at least four evolving rivals**, with five as the preferred prototype target.

## 3. Rival State

**PROPOSAL**

Each rival should track a compressed state:

- competitive strength;
- roster core / open needs;
- coach/staff quality summary;
- cash / financial posture band;
- reputation;
- audience / sponsor attractiveness;
- strategic posture;
- current major contracts / commitments;
- current sponsor relationship summary.

No detailed internal department simulation is required.

## 4. Rival Strategic Postures

**PROPOSAL**

A small set of dynamic postures is sufficient:

- contend / spend for immediate strength;
- balanced;
- develop / rebuild;
- stabilize / conserve cash.

Posture is not a permanent personality class. It can change with results, finances, roster age/value, and opportunities.

## 5. Rival Decision Windows

**PROPOSAL**

Rivals make material decisions at the same kinds of windows as the player:

- transfer / signing windows;
- contract expiry periods;
- sponsor opportunity windows;
- after major competition results;
- after financial deterioration;
- after losing key people.

Routine rival actions resolve without interrupting the player unless they materially change a player-relevant opportunity.

## 6. Minimum Rival Actions

**PROPOSAL**

Rivals must be able to:

- sign / release / retain players;
- compete for selected free agents;
- change coach / staff quality at abstract depth;
- accept sponsor opportunities;
- alter strategic posture;
- spend more or less based on financial condition;
- rebuild after poor performance;
- improve or decline over time.

## 7. Rival Decision Logic

**PROPOSAL**

A rival should choose among feasible actions based on:

- current posture;
- resource constraints;
- roster/staff need;
- expected competitive value;
- financial risk;
- opportunity timing;
- relative attractiveness of alternatives.

The rival does not need perfect optimization. It needs coherent, explainable behavior that changes state.

## 8. Fairness Rule

**PROPOSAL**

Rivals may use compressed information and decision logic, but they should not bypass ecosystem constraints.

They should:

- pay meaningful costs;
- lose access when another organization signs a target;
- suffer from bad commitments;
- enter rebuild/stabilize states;
- face sponsor/talent availability limits.

This preserves shared-world credibility without requiring identical simulation depth.

## 9. Rival Consequences on Player

**PROPOSAL**

A rival action should matter only when it changes at least one of:

- opponent strength;
- talent availability / price;
- sponsor availability / value;
- standings / qualification stakes;
- reputation / audience competition;
- future strategic opportunity.

## 10. Rival Acceptance Criteria

**PROPOSAL**

The rival model is sufficient when a multi-cycle test can show:

- at least one rival improves while another declines;
- a rival can take a player target or sponsor opportunity;
- a rival can rebuild after poor performance;
- player strategy changes because of rival behavior;
- rivals do not need scripted event text to create these pressures.

## 11. Open Questions

**OPEN QUESTION**

- Exact organization count required by the selected competition format.
- Whether rivals can use debt in the first prototype.
- How visible rival financial posture should be to the player.
- Whether sponsor opportunities are exclusive to one organization or can support category-based competition.
